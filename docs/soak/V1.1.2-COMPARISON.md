# v1.1.2 soak — run-1 vs re-verification comparison

Both runs: same binary version line (`blackbox 1.1.2`), same isolated Daytona
sandbox class (1 effective CPU / 1 GiB cgroup RAM, kernel `6.17.0-35-generic`,
3.0 GB overlay disk), same workload (6 paced workers ≈ 150 req/s,
`TOKIO_WORKER_THREADS=2`), same 48 MiB RAM budget, same crash schedule
(T+600 s, T+1200 s). The only code difference is the streaming sidecar
indexer (plus its parity test) — `frame::parse_header` + the frame-by-frame
`walk_idx_entries` replacing `read_to_end`/`decode_all` in the compactor.

## What the charts show

**rss-timeline.svg** — Node A (top) and Node B (bottom) VmRSS over the
30-minute window. Run-1 (red) rides visibly higher on Node A and pokes above
the `Warn75` line right at the compaction window around t≈1490 s, where the
`Shed85` finalizer head-sampled 7 healthy fast-2xx records (marked). The
re-run (green) sits lower everywhere and never leaves `Normal`: the multi-MB
`read_to_end` transient that crossed the watermark is gone — at most one
frame (≤ 64 KiB payload) is resident while indexing. Dotted verticals mark
the two injected upstream-crash recoveries (present in both runs).

**soak-comparison.svg** — per-node peak RSS (both under the 45 MiB target in
the re-run), sampled-out records (7 → 0), and soak checks passed (19 → 20 of
20). Node B was already `Normal` in run-1 and stayed `Normal` — the fix
targets the Node A compaction path; B's improvement reflects the same walker
running on its 2 MiB segments (37 compactions).

```
python scripts/soak/soak-graphs.py <RUN1_RAW> <RUN2_RAW> [--out docs/soak]
```

Defaults point at the two evidence directories above. Sampling is kernel
`VmRSS` every ~10 s; brief peaks between samples can be missed; a 30-minute
window cannot establish absence of a long-term leak.

## Honest-semantics notes

- `Shed85` is a *head-sampling* finalizer: when it fires it keeps ~1 % of
  healthy fast-2xx traces while errors and slow traces stay at 100 %. The
  PASS target is that it never fires under this workload — in the re-run it
  never fired.
- `Backpressure95` is published but never enforced; no HTTP path gates on it
  in either run.
- Node B improvements are real but secondary: B already passed in run-1.
  The decisive evidence is Node A, where the compaction transient lived.
